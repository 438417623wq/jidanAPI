# #49 设置页准入兼容修复

## 范围与假设

- 设置 API 与模型调用是独立入口；本次修复设置 API 的备用准入检查。
- 服务对象逐请求查找，继续优先采用宿主 `connection.admit` 的决定。
- 已复现：桌面代理移除 Origin 和 Sec-Fetch-Site，保留 `dsh-app://app/` Referer；原备用检查拒绝该请求。
- 只接受此桌面来源的精确 authority，且要求没有 Origin、Sec-Fetch-Site，Host 仍须为回环地址。
- 正常请求不增加日志；拒绝日志仅包含固定的入口、状态、来源、原因，不包含请求头、URL、Cookie、Token 或异常正文。
- 本次不调整模型、用户配置、发布签名或升级流程；宿主鉴权服务抛错时停止准入。

假设：桌面代理行为以本机 DSH Desktop 0.2.0-rc.2 的实际安装代码为依据。#49 没有提供版本和失败请求，不能认定 issue 的真实原因已经确认。

## 决策记录

| 方案 | 决定与原因 |
| --- | --- |
| 仅兼容桌面代理格式 | 采用；保留普通 HTTP 同源检查，并限制允许的桌面 authority 和头部形态。 |
| 移除所有 Referer 检查 | 不采用；扩大现有备用检查的放行范围。 |
| 仅增加诊断 | 不单独采用；可以查明拒绝来源，但不能修复已复现的误拒。 |

宿主明确返回 401/403 时不采用备用检查。宿主准入调用或服务读取抛错时返回 503，而不是降级到缺少宿主身份验证的备用检查。诊断同时覆盖 JSON API 与 SSE 入口。

## 验证要求

覆盖桌面备用检查、恶意或带凭据的桌面 Referer、Origin/Fetch-Metadata 未清除、跨站与非回环 Host、宿主 401/403、宿主异常、迟到服务，以及真实注册的 JSON/SSE 路由。执行贡献者离线测试和 `git diff --check`。

这些回归验证不等同于 #49 用户环境复现；尚需现场使用拒绝日志确认路径。发布摘要及签名交由维护者按发布流程准备。
